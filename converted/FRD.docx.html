Spendid Project – Functional Requirements Document (FRD)

Brokerage Finance Operations Command Center
Version 1.0 – 2026‑10‑10

1. Executive Summary

Meridian Brokerage Group needs a single, AI‑augmented “Finance Operations Command Center” that gives the CFO, Controllers, and Finance Operations teams a real‑time, material‑exception‑centric view of cash, receivables, carrier payables, producer commissions, and month‑end close. The solution must detect, classify, and prioritize financially material exceptions across heterogeneous legacy sources, surface actionable insights, and orchestrate human‑in‑the‑loop resolution while preserving segregation‑of‑duties, auditability, and regulatory compliance.

The Command Center will be built as an enterprise‑grade, container‑native web application with a conversational AI Copilot (Streamlit‑based) that leverages a vetted LLM (Azure OpenAI GPT‑4o) for exception intelligence, forecasting, and natural‑language query. All data will reside in a PostgreSQL data‑warehouse; synthetic data generators will seed the environment for development, testing, and demo.

2. Objectives

# Objective Business Value
O‑1 Provide a single source of truth for all finance‑process exceptions (cash, receivables, payables, commissions, close) Eliminates fragmented spreadsheets & manual reconciliations
O‑2 AI‑driven classification & materiality ranking of exceptions to surface high‑impact items first Reduces leakage, accelerates settlement
O‑3 Enable persona‑driven dashboards (CFO, Controller, Ops, Treasury, Agency Finance) Improves decision speed & accountability
O‑4 Offer a conversational Copilot that can answer “why” and “what‑if” questions with traceable evidence Lowers cognitive load, speeds root‑cause analysis
O‑5 Enforce segregation of duties and human approval for any ledger, payment, or commission change Controls fraud & regulatory risk
O‑6 Deliver audit‑ready logs, immutable evidence, and compliance reports (SOC 2, ISO 27001, GLBA) Supports internal & external audits
O‑7 Provide scalable, cloud‑native deployment with auto‑scaling, zero‑downtime upgrades, and observability Guarantees availability during peak periods
O‑8 Capture tokenomics & model economics to optimise AI cost vs. latency Ensures sustainable AI consumption

State Description Owner SLA
Ingestion Files (lockbox, carrier statements, commission feeds) land in Azure Blob Storage via secure transfer. System ≤ 5 min
Validation Schema & checksum validation; malformed records flagged. System (AI‑Validator) ≤ 2 min
Classification LLM agent tags exception type, materiality score, probable cause. AI Copilot ≤ 3 sec per record
Prioritization Engine ranks exceptions by exposure, aging, control impact. System (Rule Engine) ≤ 1 sec
Workbench Exception appears in user queue with evidence bundle. Assigned Finance Analyst Real‑time
Investigation Analyst adds notes, uploads supporting docs, may request additional data. Analyst ≤ 2 days (default)
Decision Analyst selects Approve, Reject, or Escalate. Analyst / Manager Immediate
Approved Generates journal‑support package, triggers downstream workflow (payment, posting). Treasury / Compensation Manager ≤ 4 hrs
Rejected Exception closed with reason code. Analyst Immediate
Escalated Auto‑escalates to CFO or Controller if SLA breach or exposure > $100k. CFO / Controller ≤ 4 hrs
Execution System posts journal entry, updates ledger, notifies stakeholders. System ≤ 30 min
Closed Final state; immutable audit record created. System N/A

6. Functional Requirements

Notation – Each requirement is uniquely identified (FR‑\<n>) and traceable to personas, UI, and tests.

ID Requirement Description Priority Source
FR‑1 Finance Journey Model Define 7 finance journeys (Cash‑to‑Carrier, Agency Bill, Direct Bill, AR, Payables, Producer Compensation, Month‑End Close) with stages, controls, owners, cut‑offs, SLAs. Must Business Stakeholders
FR‑2 Synthetic Finance Ledger Store all transaction primitives (receipts, invoices, statements, reconciliations, commissions, adjustments, close tasks) in normalized PostgreSQL schema. Must Architecture
FR‑3 Ingestion Engine Securely ingest lockbox files, carrier statements, commission feeds via Azure Event Grid → Azure Functions → Blob → Staging tables. Must Technical
FR‑4 Data Validation Service Apply schema, checksum, and business‑rule validation (e.g., amount > 0, date within period). Flag malformed records for manual review. Must FR‑3
FR‑5 AI Exception Classification LLM (GPT‑4o) receives validated record, returns: exception type, materiality score (0‑100), probable cause, confidence %, suggested next step. Must AI Strategy
FR‑6 Materiality Ranking Engine Combine AI score, exposure amount, aging, control impact to produce a Priority Score (0‑1000). Configurable weighting per persona. Must FR‑5
FR‑7 Command‑Center Dashboard Persona‑driven UI showing: cash position, aging buckets, settlement exposure, commission exceptions, reconciliation status, close readiness, KPI trend charts. Must UI/UX
FR‑8 Exception Workbench Queue view with filters (type, priority, owner, SLA), evidence panel (raw file, AI reasoning, audit trail), action buttons (Assign, Approve, Reject, Escalate). Must UI/UX
FR‑9 Conversational Copilot Chat interface (Streamlit) that accepts natural‑language queries, returns grounded answers with citations to ledger rows, AI reasoning, confidence, and assumptions. Must AI Agent
FR‑10 Controlled Action Orchestration Generate Task Packages (investigation, journal‑support, approval request) that require explicit human sign‑off before any ledger write. Must Workflow
FR‑11 Segregation‑of‑Duties Enforcement System enforces that the user who creates a journal entry cannot approve it; role‑based matrix stored in Azure AD. Must Security
FR‑12 Audit Trail Immutable append‑only log (Azure Log Analytics + immutable blob) capturing: user, timestamp, action, before/after values, AI prompt & response, token usage. Must Compliance
FR‑13 Notification Service Email & Teams alerts on: new high‑priority exception, SLA breach, escalation, approval required, AI low‑confidence flag. Should UX
FR‑14 Synthetic Data Generator CLI tool (Python) that creates multi‑agency transaction sets, feeds, statements, and noise; configurable volume (10 k‑10 M rows). Must Test
FR‑15 Tokenomics Tracker Middleware that records per‑request token count, latency, model version; aggregates daily/weekly for cost reporting. Should AI Ops
FR‑16 Reporting Engine Exportable CSV/Excel reports: exposure trends, close forecast, AI usage, SLA compliance, audit summary. Should Analytics
FR‑17 Role‑Based UI Rendering UI components rendered based on Azure AD group membership; no “security through obscurity”. Must Security
FR‑18 Multi‑Tenant (Agency) Isolation Logical separation of agency data via tenant_id; cross‑agency queries prohibited. Must Compliance
FR‑19 Disaster Recovery Automated backup to Azure Geo‑Redundant Storage; fail‑over to secondary AKS cluster within 15 min RTO. Must Ops
FR‑20 Performance Dashboard latency ≤ 2 sec; AI response ≤ 3 sec; ingestion throughput ≥ 5 k records/min. Must NFR

9. Security

Area Controls

Vulnerability Management Automated scans (GitHub Dependabot, Trivy, Semgrep) on each PR; quarterly pen‑test.

Least‑Privilege AI LLM calls limited to finance-exception prompt template; no retrieval of raw PII.

Incident Response Playbook in Azure Sentinel; 24‑hour initial response SLA.
