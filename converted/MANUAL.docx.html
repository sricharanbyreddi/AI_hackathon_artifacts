1. Introduction

1.1 Purpose

The Brokerage Finance Operations Command Center (hereafter Command Center) provides a single, real‑time operating view of all financially material exceptions across Meridian’s brokerage finance ecosystem. It enables:

  • Materiality‑based prioritisation of cash, commission, settlement, and close‑risk exceptions.
  • AI‑driven classification, root‑cause inference, and exposure quantification with traceable evidence.
  • Controlled, auditable actions (journal entries, approvals, payouts) that enforce segregation of duties (SoD) and regulatory compliance (SOC 2, ISO 27001, GDPR‑like data‑privacy).
  • Conversational Copilot for on‑demand, persona‑specific insight (“Why is cash unapplied?”).

1.2 Key Benefits

1.3 Terminology (Glossary)

Term Definition
Exception Any deviation from expected financial control (e.g., unapplied cash, duplicate transaction).
Materiality Score AI‑computed ranking (1‑5) based on exposure amount, control impact, and deadline risk.
Copilot Conversational AI assistant (LLM‑powered) that answers finance‑specific queries with evidence.
Workbench UI module where exceptions are inspected, classified, and routed for resolution.
Ledger‑Trace End‑to‑end provenance from source document to GL posting, stored in immutable audit logs.
SoD Segregation of Duties – enforced via role‑based access control (RBAC).

3. Screen Descriptions

Note: All screens are responsive; the layout adapts to 1920×1080 workstations and 1440×900 laptops.

3.1 Login Screen

Element Description Security
Username / Email SSO‑linked corporate identifier. Input sanitised; no plaintext storage.

3.4 Copilot (Chat Overlay)

UI Element Description
Prompt Input Free‑text entry; auto‑suggests finance‑specific intents (e.g., “unapplied cash”, “settlement at risk”).
Response Pane AI answer with:
• Answer (plain text)
• Evidence (linked documents, data points)
• Confidence (0‑100 %)
• Assumptions (list).
Action Buttons (below response) Create Task, Open Workbench, Request Approval (if answer suggests monetary action).
History Scrollable log of prior queries; each entry is immutable and searchable.
Safety Guardrails If confidence < 70 % or request involves monetary movement, Copilot returns “I need human confirmation” and logs a Human‑Review Required flag.

3.5 Action Orchestration Wizard

A step‑by‑step modal that guides the user through a controlled resolution:

  1. Select Exception(s) – pre‑populated from Workbench.
  2. Proposed Action – AI‑suggested (e.g., “Create journal entry $X to offset unapplied cash”).
  3. Review Evidence – auto‑generated PDF attachment (tamper‑evident hash).
  4. Assign Approver – based on SoD matrix (e.g., Treasury Manager).
  5. Submit for Approval – triggers workflow engine (Camunda BPM) and sends secure email/SMS to approver.

3.6 Approval Hub

Column Description
Request ID Unique UUID, immutable.
Exception ID(s) Linked exceptions.
Proposed Action Text + monetary amount.
AI Confidence %; if < 80 % requires additional reviewer.
Approver Auto‑filled based on role.
Decision Approve / Reject / Request More Info.
Audit Log One‑click “View Evidence”.

3.7 Audit Log Viewer

Feature Details

Search Full‑text, filter by user, date, exception ID, action type.
Export Signed JSON (SHA‑256) for regulator submission.
Retention 7 years (configurable per policy).

4. Workflow Guide

Below is the end‑to‑end “Cash‑to‑Carrier Exception” flow, the most common scenario.

4.1 Scenario Overview

Malformed lockbox file → Unapplied cash → Exception generated → AI classification → Human review & approval → Journal entry → Cash position updated → Close‑readiness score improves.

4.2 Step‑by‑Step Walkthrough

Step Actor UI Action System Reaction Audit Record
1 System Ingest lockbox file (SFTP). File parsing service detects malformed rows → creates Exception #E‑2026‑00123 (type: Unapplied Cash). EVENT:FILE_INGEST, EXCEPTION_CREATED.
2 AI Engine Runs Exception Classification Agent (LLM + rule‑engine). Assigns Materiality = 4, Confidence = 92 %, Suggested Action = “Create journal entry to apply cash”. AI_CLASSIFY, AI_EVIDENCE_HASH.
3 Finance Ops Analyst Opens Workbench, filters by Materiality ≥ 4. Exception appears at top of queue. USER_VIEW, FILTER_APPLIED.
4 Analyst Clicks Details, reviews source PDF, AI evidence. UI shows highlighted line “Record #45 missing account number”. EXCEPTION_VIEWED.
5 Analyst Clicks Open Copilot, asks “Why is cash unapplied?”. Copilot returns answer with 94 % confidence, cites missing account number, provides link to lockbox row. COPILOT_QUERY, COPILOT_RESPONSE.
6 Analyst Clicks Create Journal (wizard). Wizard pre‑fills amount $125,000, debit “Unapplied Cash”, credit “Cash Receivable”. JOURNAL_WIZARD_INIT.
7 Analyst Assigns Treasury Manager as Approver, adds comment “Review lockbox row #45”. Workflow engine creates approval task, sends encrypted push notification. APPROVAL_TASK_CREATED.
8 Treasury Manager Logs in, opens Approval Hub, reviews evidence, clicks Approve. System posts journal entry, updates GL, recalculates cash‑position KPI. APPROVAL_GRANTED, GL_POSTED.
9 System Sends Audit Log entry with cryptographic hash of all documents involved. Log retained for 7 years, visible in Audit Viewer. AUDIT_LOG_ENTRY.
10 CFO Views updated Executive Dashboard – Materiality score drops to 2, cash‑position KPI improves. Dashboard auto‑refreshes via WebSocket. DASHBOARD_REFRESH.

4.3 Alternate Paths

  • Low Confidence (< 70 %) – Copilot returns “I’m not confident; please involve a senior analyst.” The system forces a Manual Classification step.
  • Duplicate Transaction Detected – AI clusters two exceptions; the Workbench shows a Merge action to avoid double counting.
  • Live‑Injected Exception – Judges can upload a new CSV via /admin/inject; the system creates a new exception without code changes (dynamic schema).

5. Frequently Asked Questions (FAQs)

# Question Answer
1 Do I need a separate password for the Command Center? No. Authentication is via corporate SSO (Okta/Azure AD) with MFA.
2 Can the Copilot execute a payment automatically? No. Copilot can only suggest actions. Any monetary movement must be approved through the Approval Hub and recorded in the immutable audit log.
3 What data is stored in the AI model’s memory? Only ephemeral embeddings for the current session; all prompts, responses, and evidence are persisted in the audit log with user ID and timestamp. No raw policy or personal data is retained beyond the session.
4 How is data encrypted at rest and in transit? All data at rest is encrypted with AES‑256‑GCM (AWS KMS). In‑transit uses TLS 1.3 with forward‑secrecy.
5 What compliance frameworks does the system satisfy? SOC 2 Type II, ISO 27001, PCI‑DSS (for payment‑related fields), and GDPR‑like data‑privacy (right‑to‑erase synthetic data).
6 Can I export the AI evidence for a regulator audit? Yes. Use the Export button on any exception or the Audit Viewer to download a signed JSON package (SHA‑256).
7 What is the maximum file size for lockbox uploads? 250 MB per file; larger files must be split.
8 How are role changes propagated? Role updates in the IdP are synced every 5 minutes via SCIM; UI reflects new permissions on next login.
9 Is there a mobile app? Currently only a responsive web UI; a mobile‑first view is planned for Q3 2027.
10 What if the AI model is unavailable? The system falls back to rule‑based classification (deterministic) and logs a Model‑Unavailability event.
